قرار نطاق المشروع
الجهاز يعلّم أسماء الحروف الإنجليزية A–Z فقط (وليس الكلمات أو أصوات الحروف داخل الكلمات). في Learn: الحرف يظهر ويُسمَع، ثم يسجل المستخدم اسم الحرف، ويقدّم النظام نتيجة تعرف/إعادة محاولة. في Revision: يُسمع اسم الحرف بدون عرضه، ويُرفع كارت أمام الكاميرا، فيُقارن الحرف المتعرف عليه بالمطلوب.
الأجهزة: Raspberry Pi 5 + شاشة Touch + USB Webcam؛ مايك USB لم يُشترَ بعد؛ سماعة Bluetooth مؤقتًا. يوم 1: تجهيز البيانات والـAI على اللابتوب؛ يوم 2: تشغيل الأجهزة والدمج؛ يوم 3: الاختبارات والـCloud والمعرض.
قواعد واقعية لا نساوم عليها
☐  التعرف على اسم الحرف المنطوق ليس تقييمًا لجودة مخارج الحروف. لا نقول للطفل «نطقك غلط» اعتمادًا على Speech-to-Text وحده؛ نستخدم «لم أتعرف على الصوت، جرّب مرة ثانية».
☐  الحروف المنفردة مثل B / D / E / G / P / T / V وA / J / K متشابهة صوتيًا؛ أي نموذج عام قد يخطئ. اختبروا واحتفظوا بحالة «غير متأكد».
☐  لا يُستخدم وجه الطفل أو صوته الحقيقي في Dataset أو Cloud دون إذن مناسب؛ في البداية نستخدم تسجيلات متطوعين بالغين، ولا نرفع الصوت الخام.
☐  الدقة 80% شرط يجب إثباته بقياس مستقل موثق، وليس افتراضًا. نجاح OCR وحده لا يثبت دقة الـSpeech.
☐  النسخة المستهدفة بنهاية اليوم الثالث: 5 حروف عاملة End-to-End ومعها مسار واضح لتعميم A–Z. التعميم الكامل هدف إضافي إذا نجح الأساس.

D1-04 | Computer Vision Baseline
الهدف: التعرف على حرف الكارت من صورة قابلة للتصوير
مين ينفذ؟ عضو Vision
الخطوات العملية:
☐  اقرأ صورة من ملف؛ حولها grayscale؛ طبّق threshold أو adaptive threshold؛ جرّب القص على منطقة الكارت.
☐  نفّذ OCR بحروف A–Z فقط وبـsingle-character page segmentation مناسب؛ نظّف النتيجة.
☐  قارِن prediction بـexpected؛ اعرض input, processed, predicted, confidence إن توفر وإلا اكتب «غير متوفر».
☐  ضع threshold أو حالة UNKNOWN إذا كانت نتيجة OCR فارغة/متعددة/مشكوكًا فيها.
☐  شغّل batch على صور test واحسب accuracy وconfusion matrix؛ سجل حالات الفشل.
إنت تقول/تسأل إيه؟
• «إيه الفرق بين preprocessing وinference؟»
• «لو الكاميرا رجّعت فراغ، هل نعتبره خطأ أم UNKNOWN؟ وكيف نحسبه؟»
Definition of Done: Script من command line يقرأ صورة ويرجع حرفًا واحدًا أو UNKNOWN + تقرير دقة
الدليل اللي يتحفظ: src/card_recognition.py + results/camera_trials.csv
لو حصلت مشكلة: لو OCR فشل: استخدموا كروت أقوى تباينًا، قص الصورة، إضاءة ثابتة؛ HOG+SVM خيار بديل يحتاج تدريب وتقييم مستقل.
D1-05 | Speech AI Feasibility — اختبار صعب ومهم
الهدف: اختيار طريقة واقعية للتعرف على اسم حرف منطوق
مين ينفذ؟ عضو Audio بقيادتك
الخطوات العملية:
☐  ثبتوا تعريف واضح: نريد «اسم الحرف» spoken letter name وليس phoneme في كلمة.
☐  سجلوا على اللابتوب أمثلة لأسماء A–E من متحدثين بالغين في غرفة هادئة؛ لكل ملف label + speaker_id مجهول + take + noise.
☐  شغّلوا نموذج Vosk small English أو ASR آخر Offline حسب الجهاز؛ اختبروا الكلمة الناتجة لكل تسجيل.
☐  طبعًا النموذج قد يرجع كلمات شبيهة (bee, be, B)، اعملوا mapping موثق للحروف، ولا تختاروا mapping بعد رؤية نتائج الـtest.
☐  اختبروا على تسجيلات جديدة من متحدثين مختلفين؛ احسبوا نسبة correct، وUNKNOWN، والأخطاء الحرجة بين الحروف المتشابهة.
☐  لو الدقة ضعيفة: اعترفوا بالنتيجة ولا تدعوا أنه phoneme scorer. قرروا تدريب classifier صوتي خاص بالـ26 أسماء حرف باستخدام MFCC+SVM أو embeddings، مع بيانات أكثر وتقسيم speakers مستقل.
إنت تقول/تسأل إيه؟
• «هل model بيعرف الصوت اتقال ولا بيقيس جودة النطق؟»
• «ليه B وD وP خطيرين لو النموذج بيسمع ثانية واحدة بس؟»
• «لو ما اتعرفش على صوت الطفل، المفروض الجهاز يقول إيه؟»
Definition of Done: جدول تجارب حقيقي يثبت صلاحية النموذج أو عدم صلاحيته، وقرار مسجل بشأن الحل
الدليل اللي يتحفظ: data/audio_eval + results/speech_trials.csv + docs/speech_decision.md

سكريبت الشرح — كلام جاهز تقوله للتيم
افتتاح أول يوم
«إحنا مش هنبدأ بتركيب Raspberry النهارده، لأن الجهاز مش وصل. هنستغل الوقت في الجزء الأصعب: نحدد الحرف المطلوب ونعرف الـAI بيقدر يتعرف على الكارت أو الصوت بدقة قد إيه. كل Task لازم يطلع منه ملف أو نتيجة، مش مجرد تجربة».
شرح الـAI للصورة
«الصورة داخلة Pixels. بنظبط التباين ونقص الكارت، وبعدها الـOCR أو classifier يتوقع الحرف. وبما إن عندنا حرف حقيقي مكتوب في الجدول، نقارن ونحسب Accuracy. لو الصورة مش واضحة، نطلع UNKNOWN بدل ما نخترع حرف».
شرح الـAI للصوت
«إحنا بنعلم اسم الحرف، مش بنشخص مخارج الحروف. نموذج تحويل الكلام لنص ممكن يسمع حرف B على إنه كلمة bee. لذلك هنقيس الأداء بنفسنا ولو مش متأكدين هنقول حاول تاني بدل نعتبر الطفل غلط».
شرح الـIoT
«الـAI ممكن يشتغل Offline، لكن شرط الـCapstone إن فيه wireless transfer للـCloud. هنرسل نتيجة المحاولة والأداء فقط، مش صوت أو صورة الطفل. لما الإنترنت يقع، اللعبة تفضل شغالة».
إغلاق أي يوم
«افتحوا قائمة التاسكات. كل تاسك لازم Proof: صورة، كود، CSV، فيديو، أو Metrics. أي حاجة من غير دليل هتفضل In Progress».

أوامر اليوم الأول — على اللابتوب
Windows (PowerShell):
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install numpy opencv-python pillow pytesseract scikit-learn sounddevice soundfile
pip freeze > requirements.txt
Linux / macOS:
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install numpy opencv-python pillow pytesseract scikit-learn sounddevice soundfile
pip freeze > requirements.txt
ملاحظة تنفيذية: Tesseract executable يُثبت منفصلًا. نموذج Vosk يُنزَّل منفصلًا أيضًا حسب الـOS. لا نثبت كل المكتبات عشوائيًا على Pi قبل تجربة توافقها.
